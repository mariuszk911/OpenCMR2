# `game/` divergence manifest

The AmigaOS port keeps `game/` as close to CMR2Decomp/OpenCMR2 as it can.
Every place where the port's `game/` still differs from upstream is listed
here, with the reason the port interfaces could not cover it and how to
re-apply the change after an upstream sync. `tools/game_divergence.py` reads
this table and fails when a differing `game/` file is missing from it.

## Divergence manifest

`game/` follows CMR2Decomp. Amiga behaviour belongs in fork-owned files behind
the existing `port/` interfaces. A `game/` edit is an exception:

1. it fixes a proven portability bug that the port API cannot cover;
2. it is approved before editing;
3. it is the smallest possible diff;
4. it carries a `// PORT: AMIGA ...` comment with the reason;
5. it is listed below with a re-apply procedure.

`game/Menu.h` itself is not patched. Domain A C++ force-includes
`src/port/menu_layout.h`, which defines the game header's `_MENU_H` guard and
provides fork-owned, ABI-identical `Menu`/`MenuItem` structures with the flag
bitfields declared in reverse order. GCC 6.5 allocates bitfields MSB-first, so
the reversal makes the in-memory byte match MSVC's LSB-first order that
`MENU_FLAGS` reads. `#pragma scalar_storage_order` does not change bitfield
order on this toolchain (verified by disassembly). The expected sizes, offsets
and prototype types live in `src/port/menu_layout_abi.h`; the shim's static
asserts and the 32-bit host test `tests/menu_layout_host.cpp` both use them, so
an upstream `game/Menu.h` change fails the host test. `tests/amiga/menu_layout_test.cpp`
checks the raw bytes on the target. Keep the header in sync with `game/Menu.h`
after an upstream sync.

An upstream-sync conflict outside this table is either an accidental
divergence or a new upstream feature that must be absorbed deliberately.
Neither is resolved by silently keeping the local side.
